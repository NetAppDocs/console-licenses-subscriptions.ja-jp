= Licenses and subscriptionsに関するよくある質問
:hardbreaks:
:allow-uri-read: 
:nofooter: 
:icons: font
:linkattrs: 
:imagesdir: ./media/


[role="lead"]
このページでは、NetApp ConsoleのLicenses and subscriptionsに関するよくある質問への回答を提供しています。直接ライセンス、Marketplaceサブスクリプション、プライベートオファー、Keystoneサブスクリプション、および請求に関する設定を管理する際に役立つ概念、決定事項、および制約について説明します。



[[overview-and-access]]
== 概要とアクセス

.NetApp Consoleにおける直接ライセンス、Marketplaceサブスクリプション、およびKeystoneサブスクリプションの違いは何ですか？
* *直接ライセンス*はNetAppから購入し、通常はライセンスファイル、シリアル番号、または容量のエンタイトルメントを使用して管理します。一般的にBring Your Own License（BYOL）と呼ばれます。
* *マーケットプレイスサブスクリプション*は、AWS Marketplace、Azure Marketplace、またはGoogle Cloud Marketplaceを通じて購入または有効化されます。料金はクラウド プロバイダを通じて請求されます。
* *Keystoneサブスクリプション*は、NetAppの従量課金契約です。NetAppがお客様のConsoleアカウントを承認すると、対象となるCloud Volumes ONTAPのデプロイで、課金方法としてKeystoneを使用できるようになります。


.NetApp ConsoleにLicenses and subscriptionsが自動的に表示されないのはなぜですか？
ライセンスとサブスクリプション情報は、ConsoleアカウントがNetApp Support Site（NSS）アカウントにも関連付けられている場合にのみ自動的に表示されます。ConsoleアカウントがNSSアカウントに関連付けられていない場合は、ライセンスを手動で追加する必要があります。使用状況、容量、その他の詳細情報も自動的に更新されません。 https://docs.netapp.com/us-en/console-setup-admin/task-adding-nss-accounts.html["NetAppサポートサイトアカウントをコンソールの資格情報に追加する方法を学びます"^]

.Licenses and subscriptionsを確認するには、Consoleエージェントが必要ですか？
サブスクリプション情報を表示するには、コンソールエージェントをデプロイする必要があります。Cloud Volumes ONTAPの直接ライセンスを表示するためにも、エージェントが必要です。

.NetApp Consoleでは、どのサービスのライセンスとサブスクリプションを管理できますか？
バックアップとリカバリ、クラウド階層化、Cloud Volumes ONTAP、災害復旧（BYOLのみ）、およびランサムウェア対策のLicenses and subscriptionsを管理できます。

.NetApp ConsoleでLicenses and subscriptionsを管理できるロールは何ですか？
Licenses and subscriptions管理者ロールを持つユーザーは、直接ライセンスの追加、編集、削除、およびMarketplaceとKeystoneサブスクリプションの関連付けまたは関連付け解除を行うことができます。

該当する閲覧権限を持つユーザーは、Licenses and subscriptionsを閲覧できますが、変更を加えることはできません。

.概要ダッシュボードから新しいライセンスやサブスクリプションを追加できないのはなぜですか？
概要ダッシュボードは、既存のライセンス問題を確認し、解決することを目的としています。直接ライセンスを追加するには、*直接ライセンス*に移動してください。マーケットプレイスのサブスクリプションを追加または関連付けるには、*マーケットプレイスのサブスクリプション*に移動してください。

.ライセンスやサブスクリプションに注意が必要かどうかは、どうすればわかりますか？
概要ダッシュボードの*対応が必要*タイルは、有効期限が切れる、または容量制限に達するLicenses and subscriptionsについて警告します。*解決*が表示されない場合は、対処が必要な問題はありません。*解決*を選択すると、*Licenses*または*Subscriptions*タブから問題を表示して対処できるページに移動します。



[[direct-licenses-byol]]
== 直接ライセンス（BYOL）

.NSSアカウントを関連付けることと、ライセンスファイルを手動でアップロードすることの違いは何ですか？
ConsoleアカウントをNSSアカウントに関連付けることで、Consoleがライセンスを自動的に検出して更新できるようになります。ライセンスを追加または更新するためにシリアル番号を入力する場合にも必要です。

コンソールがインターネットに接続されていない場合、またはコンソールアカウントがNSSアカウントに関連付けられていない場合は、NetAppライセンスファイルを手動で取得してアップロードする必要があります。このような場合、コンソールはライセンスを自動的に照会または更新することはできません。

.Cloud Volumes ONTAPの容量ベースとノードベースのBYOLライセンスの違いは何ですか？
* *容量ベースのBYOLライセンス*の場合、ライセンスは単一のシステムではなく、Consoleアカウントに関連付けられます。各システムには固有のシリアル番号が割り当てられますが、同じアカウントに属する複数のシステムは共有容量プールから容量を使用します。
* *ノードベースのBYOLライセンス*の場合、プーリングは適用されません：各Cloud Volumes ONTAPシステムには専用のシステムライセンスが必要ですが、元のシステムを削除すれば、新しいシステムにライセンスを移行できます。


ノードベースのライセンスは、旧世代のモデルです。NetAppは、すべての新規導入に容量ベースのライセンスを推奨しており、既存のノードベースのライセンスは変換する必要があります。 https://docs.netapp.com/us-en/storage-management-cloud-volumes-ontap/task-convert-node-capacity.html["ノードベースのライセンスを容量ベースのライセンスに変換する方法"^]。

.未割り当てのCloud Volumes ONTAPライセンスを別のサービスと交換するとどうなりますか？
未割り当てのCloud Volumes ONTAPライセンスを交換すると、そのライセンスは取り消され、新しいサービス（NetApp Backup and Recovery、データ分類、またはクラウド階層化）の同額のライセンスが作成されます。

* HAペアのライセンスは、51 TiBの直接ライセンスに変換されます。
* 単一ノードのライセンスは、32 TiBの直接ライセンスに変換されます。


変換されたライセンスは、元のCloud Volumes ONTAPライセンスと同じ有効期限を保持します。

.BYOLライセンスとPAYGOマーケットプレイスサブスクリプションのどちらが請求されているかを確認するにはどうすればよいですか？
コンソールは、まず利用可能なNetAppライセンスに対して使用料を請求しようとします。十分なライセンス容量が利用できない場合は、連携しているマーケットプレイスのPAYGOサブスクリプションに対して使用料が課金されます。

容量ベースのライセンスパッケージを変更しても、使用量がNetAppで購入したライセンス（BYOL）を通じて課金されるか、マーケットプレイスのPAYGOサブスクリプションを通じて課金されるかは変わりません。BYOLライセンスをマーケットプレイスのサブスクリプションに変換したり、その逆を行ったりする必要はありません。

.マーケットプレイスの契約に含まれていない課金方法を選択した場合、どうなりますか？
マーケットプレイスの個別オファーまたは契約に含まれていない課金方法を選択した場合、そのマーケットプレイスパッケージは使用できません。使用料は、利用可能な場合はNetAppライセンスに対して課金されるか、代わりにPAYGOを通じて課金されます。



[[marketplace-subscriptions-and-private-offers]]
== マーケットプレイスのサブスクリプションとプライベートオファー

.1つのAzureサブスクリプションまたはGoogle Cloudプロジェクトに、いくつのMarketplaceサブスクリプションを関連付けることができますか？
Azure サブスクリプションまたは Google Cloud プロジェクトは、1 つの Marketplace サブスクリプションにのみ関連付けることができます。同じ Azure サブスクリプションまたは Google Cloud プロジェクト内のワークロードに 2 つの異なる Marketplace サブスクリプションを使用する場合は、サブスクリプションごとに 1 つずつ、2 つの別々の Console アカウントを作成する必要があります。

.Licenses and subscriptions からマーケットプレイスのサブスクリプションを削除できるのはいつですか？
ステータスが*Unsubscribed*のサブスクリプションのみを削除できます。また、削除する前に、関連するすべての設定、データ、構成をクリアまたはリセットする必要があります。サブスクリプションがまだ設定されている場合は、*Remove*オプションは利用できません。link:task-manage-subscriptions.html#remove-a-subscription["サブスクリプションを削除する方法"^]。

.プライベートオファーを複数回承諾または有効化するリスクは何ですか？
プライベートオファーを複数回承諾して有効化すると、二重請求が発生する可能性があります。承認手続きにおいて必要な手順を省略すると、請求エラーやアクティベーションの問題が発生する可能性があります。

.プライベートオファーの条件、価格、または詳細が間違っているように見える場合はどうすればよいですか？
オファーの条件、価格、詳細に相違点がある場合、またはどのオファーを受け入れるべきか不明な場合は、そのオファーを受け入れないでください。手続きを進める前に、NetAppの営業チームまたはアカウントチームに連絡して確認してください。

.変更後のGoogle Cloudプライベートオファーを受け入れた場合、または既に有効なPAYGOサブスクリプションをお持ちの場合はどうなりますか？
既に有効なPAYGOサブスクリプション、または変更されたプライベートオファーをお持ちの場合は、承認手順のみを実行してください。このような場合、Google Cloud Marketplace は同じリスティング内のプランを更新し、同じサブスクリプション ID を保持するため、コンソールでのサブスクリプションの関連付けはそのまま維持されます。

.無料トライアルの請求アカウントを使用して、Google Cloudのプライベートオファーを受け入れることはできますか？
いいえ。Google Cloudの請求アカウントは無料トライアル期間中であってはなりません。無料トライアルアカウントでは、プライベートオファーを受け取ることができないためです。トライアル請求アカウントを使用しようとするとエラーが発生し、NetAppクラウドチームのサポートが必要になります。

.複数のAWSサブスクリプションタイプを使用したり、複数のリスティングを移行したりした場合、二重に課金されますか？
複数のサブスクリプションタイプを使用したり、リスティング間を移行したりしても、重複した計測は発生しません。



[[keystone-subscriptions]]
== Keystoneサブスクリプション

.Keystoneサブスクリプションを使用する前に、NetAppがコンソールアカウントを承認する必要があるのはなぜですか？
Keystoneサブスクリプションを使用または管理する前に、NetAppがお客様のConsoleアカウントを承認する必要があります。この承認により、対象となるKeystoneサブスクリプションがNetApp Consoleで利用可能になります。*Welcome to NetApp Keystone*ページが表示された場合は、そのページに記載されている連絡方法に従って承認をリクエストしてください。link:task-manage-keystone.html#authorize-your-account["Keystoneサブスクリプションのアカウント承認の詳細"^]。

.Keystoneサブスクリプションをリンクするとどうなりますか？
Keystoneサブスクリプションをリンクすると、Consoleの組織またはアカウントに関連付けられ、新しいCloud Volumes ONTAP作業環境を作成する際の課金方法として利用できるようになります。

.Keystoneサブスクリプションのリンクはいつ解除できますか？
Keystoneサブスクリプションのリンクを解除できるのは、既存のCloud Volumes ONTAPサブスクリプションに関連付けられていない場合のみです。

.Keystoneサブスクリプションのコミットされたキャパシティの変更をリクエストするにはどうすればよいですか？
1つ以上のサブスクリプションに対して要求するコミット済み容量を入力し、追加の詳細情報を送信することで、コンソールから直接NetAppにリクエストを送信できます。これにより、処理のためにNetAppのシステムにチケットが作成されます。



[[billing-preferences]]
== 請求設定

.「NetAppライセンス優先」と「Marketplaceサブスクリプションのみ」の課金モードの違いは何ですか？
「NetAppライセンス優先」は、アクティブなNetAppライセンスを通じた請求を優先し、その容量を使い果たすと、使用量はリンクされたMarketplaceサブスクリプションに引き継がれます。「Marketplaceサブスクリプションのみ」は、すべての請求をMarketplace契約経由で行い、NetAppライセンスを完全にバイパスします。これは、クラウド プロバイダの請求を通じて調達を標準化している組織で一般的です。

.請求設定でカスタムCVO構成を有効にすべきタイミングはいつですか？
組織が以下のことを必要とする場合は、カスタムCVO構成を有効にしてください：

* 事業部門や環境によって管理する請求アカウントが異なるため、同じクラウド プロバイダ内の個々のCloud Volumes ONTAPインスタンスに複数のMarketplaceサブスクリプションをマッピングします。
* 1つのサブスクリプションを複数のクラウドプロジェクトにマッピングします。


例えば、ビジネスユニット A が 1 つの Azure サブスクリプションに請求し、ビジネスユニット B が別の Azure サブスクリプションに請求する場合、カスタム CVO 構成を使用すると、各ビジネスユニットの Cloud Volumes ONTAP インスタンスを独自のサブスクリプションに紐付けることができます。

.カスタムCVO設定を有効にした後で無効にした場合、どうなりますか？
カスタムCVO構成を無効にすると、すべてのCloud Volumes ONTAPの課金は、カスタムCVO構成で許可されていたインスタンスごとのサブスクリプションマッピングではなく、他のデータサービスで使用されているグローバル課金モード（NetAppライセンス優先、またはMarketplaceサブスクリプションのみ）にリセットされます。

.スタンドアロンのAWSサブスクリプションとNetApp Intelligent Services（NIS）サブスクリプションの両方がある場合、Cloud Volumes ONTAPの容量はどのように請求すればよいですか？
AWS アカウントで両方のサブスクリプションが利用可能な場合は、請求設定を使用して、Cloud Volumes ONTAP の容量課金に使用するサブスクリプションを選択できます。すでに NIS を通じて課金されている既存の Cloud Volumes ONTAP システムの場合、請求設定を更新しない限り、スタンドアロン サブスクリプションを追加しても課金内容は変更されません。スタンドアロン サブスクリプションが利用可能になったあとに作成される新しいデプロイメントでは、設定を上書きしない限り、容量課金（Essentials/Freemium）にはデフォルトでスタンドアロン サブスクリプションが使用されます。 https://docs.netapp.com/us-en/storage-management-cloud-volumes-ontap/concept-licensing.html["Cloud Volumes ONTAPライセンスパッケージの詳細について"^]。

.スタンドアロンのCloud Volumes ONTAP AWSサブスクリプションを使用して、ProfessionalパッケージまたはBackup and Recoveryの課金を行うことはできますか？
いいえ。スタンドアロンのCloud Volumes ONTAPサブスクリプションは、容量ベースのEssentialsおよびFreemiumパッケージのみをサポートしています。Professionalパッケージはサポートされておらず、引き続きNISサブスクリプションを通じて課金されます。スタンドアロンサブスクリプションのみが関連付けられている場合は、Essentialsを使用してCloud Volumes ONTAPをデプロイできますが、Backup and Recoveryの設定には別のサブスクリプションが必要です https://docs.netapp.com/us-en/storage-management-cloud-volumes-ontap/concept-licensing.html["Cloud Volumes ONTAPライセンスパッケージの詳細について"^]。

.請求設定のKeystoneフィールドは何に使用されますか？
Keystoneフィールドは、従量課金制サービスの使用状況をお客様のKeystone請求プロファイルに関連付けます。*契約ID*は、NetApp Consoleの請求記録をお客様のKeystone契約にリンクし、利用状況レポートの同期を可能にする一意の識別子です。*サービス範囲*は、Keystone契約の対象となるサービスまたは容量プールを一覧表示し、どのワークロードまたは環境が含まれるかを明確にして、対象となるリソースのみがKeystoneを通じて請求されるようにします。
